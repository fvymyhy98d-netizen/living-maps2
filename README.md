# 三张活地图 · 课程大作业网站

「人工智能前沿与创新」课程大作业：围绕所选领域，建立**领域 · 生态 · 认知**三张相互关联、持续更新的活地图。

纯前端项目（HTML + CSS + JavaScript），**无需安装任何软件、无需后端**，可托管在 GitHub Pages 上免费运行。

---

## 一、文件结构

```
living-maps/
├── index.html          网站入口（唯一 HTML 文件）
├── css/style.css       样式（Apple 官网风格）
├── js/
│   ├── app.js          渲染、路由、动画、管理员登录
│   ├── editor.js       管理模式（编辑内容 / 页面管理 / GitHub 同步）
│   ├── md.js           轻量 Markdown 引擎（行内标记 + 块级渲染）
│   ├── charts.js       图表（柱状图 / 折线图 / 饼图，纯 SVG）
│   └── store.js        数据保存（浏览器本地 / GitHub 云端）
├── data/content.js     网站内容数据（管理员同步时会自动更新此文件）
└── images/             放你自己的图片（引用方式：images/xxx.png）
```

## 二、本地预览（两种方法）

- **方法 1（最简单）**：双击 `index.html`，用浏览器打开（若个别浏览器在 file:// 下因安全策略不渲染，请用方法 2）。
- **方法 2（推荐）**：VS Code 安装 "Live Server" 扩展 → 右键 `index.html` → "Open with Live Server"，改完即时刷新。

## 三、怎么用（管理员模式）

1. 点右上角 **⚙ 设置 → 管理员模式 → 进入**，输入初始密码：`admin123`
   （另有一个只在代码里以**密钥拉伸哈希**存在的**个人专属密码**，任何界面、提示和文档都不会显示它；「修改密码」功能也改不掉这个通道，忘记管理密码时用它仍可进入）

   > 🔐 **密码安全机制（v2）**：管理密码以 **PBKDF2-HMAC-SHA256 · 60000 轮 + 独立随机盐** 保存（不再使用单轮 SHA-256）——内容文件即使泄露（如仓库公开），离线暴力反推密码的成本也被放大数万倍；旧版单轮哈希会在**下一次成功登录时自动无感升级**为 v2 并从内容里删除（**密码不用改**）；连续输错 5 次锁定 30 秒，防脚本穷举；全程不存明文。
2. **直接点击任何文字就能修改**（和 Word 一样），改完自动保存到浏览器；**Ctrl+Z 撤销 / Ctrl+Y 重做**（文档级，最多 60 步）
3. **顶部浮动工具栏**（仿 Word 的「开始 / 插入」双选项卡，苹果毛玻璃风）：

   - 点表格某格 → 出现 **＋行 −行 ＋列 −列**；**每个非最后一列的表头右缘都有竖向拖动条**（第1|2、第2|3……每个交界都能拖，即改列宽）；点图片 → 出现 **裁剪 / 边框 / 虚化 / ↺ 恢复默认**

   - **来源 / 引用系统（论文式）**：正文里被引用的话显示**虚线下划线 + 右上角上标数字**（1 2 3…按来源列表顺序）；**同一来源被多处引用 → 显示同一个数字**；阅读模式（非管理员）**点击引用文字 → 平滑滚到页尾对应来源**（条目短暂高亮），右上角淡入 **↩ 返回阅读位置**（不顶开页面、不闪屏），点击丝滑滚回原位，滚回去后按钮自动消失；选中已引用的话再点「来源」可**改挂别的来源 / 移除引用**
   - **页面管理增强**：点「图标」框弹出**预制图标面板**（32 个常用 emoji，可滚动；**点选一个即填入并自动关闭面板**，想再选就再点一次图标框，也**可以直接键盘键入**）；每页新增**「标题居中 / 居左 / 居右」**下拉；**新增页面改为虚线模板**——点弹窗底部「＋ 点击新增空白页面模板」多出一行空白模板（可加多行、可「移除」），填好后点「**保存修改**」统一创建（导航与首页卡片同步出现）；**导航名 / 页面大标题 / 页面说明留空的行，页面上不会显示（不留空白）**
   - **对齐模块（块工具条）**：自由文本框 → **六个键**：**⇤ 向左拉伸 / ⇥ 向右拉伸**（拉伸语义：向左 = 右边缘不动、左边伸到文档最左；向右 = 左边缘不动、右边伸到文档最右；被同一高度的文本框挡住时停在它旁边，留 16px 苹果风小缝）＋ **左 贴左 / 中 水平居中 / 右 贴右**（**只位移不拉伸**，宽度始终不变）＋ **⤒ 顶到上一模块底部**（框的上缘与上一个**内容块**的下缘对齐——自动跳过其他自由文本框，避免对到半空留下大片空白，**只位移**；按**自然布局**测量，不受其他框“让位”挤出的空隙影响，不会顶出一大段空白）；**↑ / ↓** 对自由框 = **整格移动**（↑ 跳到「上一模块」的**上面**、↓ 跳到「下一模块」的**下面**，一步到位、带平滑滑动动画；对普通块 = 调整文档顺序）；图片 / 表格 → **⇤ 贴左 / ⇆ 居中 / ⇥ 贴右**（本就是只位移；图片始终**等比缩放不变形**；文档流里的块天然紧跟上一模块底部，无需再对齐）
   - **☑ 勾选并排**：工具栏点 **☑** 进入勾选模式 → **点选 2-4 个内容块**（绿框 ✓ 标记，再点取消）→ 点 **▦ 并排**：它们排成一排——**上下对齐、左右手拉手留缝、高度随内容**；图片不支持并排（会提示）；**并排成功 = 自动退出勾选模式**（☑ 熄灭、绿勾与选中态全部清除），Esc 也可随时退出
   - **首页全面可编辑**：「三张地图，一个外脑。」「让地图"活"起来。」两个栏目标题、顶部小字 / 大标题 / 点题 / 简介全部**点击直接改**；**可探索 / 相关联 / 可追溯 / 可更新** 四张卡片=图标+标题+说明都可改，**悬停卡片右上角 ✕ 删除、点虚线「＋ 添加卡片」新增**；各大标题字段样式互相独立——**改顶部小字的颜色不会再串到大标题**（渐变 / 字体 / 字号同理，点哪行改哪行）
   - **来源引用更稳**：即使点按钮时选区被清掉，也会自动用**上一次拖选的话**；目标不支持时提示更明确（正文内容块可用；大标题、表格暂不支持）
4. **Markdown 块**：插入后直接在源码框里写 Markdown——支持 `# 标题`、`**加粗**`、`*斜体*`、`__下划线__`、`~~删除线~~`、`==高亮==`、`^上标^`、`~下标~`、`@@#bf3f3f,红字@@`（彩色字体）、列表、表格、引用、代码块、`[链接](网址)`、`[[r:来源ID,文字]]`（引用标记，一般用「🔗 来源」按钮生成）；**输入时实时预览**，点「✓ 转换保存」生效；源码框可上下拉伸
5. **自由文本框（像 Word 一样）**：「插入 → ▢ 文本框」即生成（出现在当前视口中部）；**拖 ⠿ 移动位置**、**拖边 / 角调整大小**；**按住拖动时滚滚轮框跟着走（不脱手），拖到屏幕上下边缘页面自动滚动**；**动态紧凑让位（带平滑动画）**：拖动过程中框压到哪个内容块，那个块就**实时渐进地**腾出刚好「框高 + 间距」的空间（不是瞬间跳动，框移走后自动回弹），不会留空隙；只有框贴着某块**下沿**（容差内）时才不触发让位——这正是防「顺序反转 / 飞升」的关键；两个文本框重叠时，被拖的框自动让到另一个下方；**字号固定不变**（拉伸只改框大小，字号用工具栏「字号」下拉改）。普通标题 / 段落仍在文档流里，文本框则可自由摆放（右上角 ↑↓ 可调层级，🗑 删除）
6. **插入位置跟随浏览位置（新增）**：没有选中任何块时，新块插入到**当前屏幕中部**所在的块后面（翻到哪里就插到哪里，不再总在最底）；选中了某个块则插到它后面；自由文本框直接出现在**当前视口中部**
7. **首页入口卡片自动同步**：「页面管理」里加几个页面，首页「三张地图」区就自动多出几张卡片（图标 / 导航名 / 标题 / 描述都在页面管理里改）；各页顶部的**大标题区**也纳入统一管理——悬停右上角出现 **🗑**（删除 / 隐藏标题区），隐藏后右上角 **👁** 常显，随时找回
8. **图片直接操作**：点击图片选中 →
   - 四角小白点：**拖动缩放**
   - 顶部小圆圈：**绕中心旋转**（接近 0°/90°/180° 自动吸附）
   - 按住图片**左右拖动移动**，靠近页面中线或两侧边界时出现**蓝色虚线对齐参考线**（自动吸附）
9. **裁剪**：选中图片 → 「裁剪」→ 拖动四角选保留区（拖中间移动选框）→ **✓ 完成裁剪**；「↺」一键恢复
10. **Word 式块选中**：**点击任意内容块**（标题 / 段落 / 表格 / 图表 / Markdown / 附件等）即选中——出现**蓝色边框 + 四角手柄**（拖角**调整块宽度**，20%~100%），右上角 **⠿ ↑ ↓ ⚙ 🗑** 工具按钮**常驻显示**（不必再悬停）；点空白处取消选中
11. **拖动排序（⠿ 把手）**：点击内容块 → 右上角工具条第一个按钮 **⠿**，**按住拖动**即可调整顺序——其他块**自动让路**（平滑动画），拖到屏幕上/下边缘时页面**自动滚动**（越靠边越快，回到中间即停），松手落位，**Esc 取消**。新块插入后用它拖到任意位置，不必一个个按 ↑↓
12. 其他：页面底部 **「＋ 添加内容块」**；Ctrl+点击 打开链接
13. 底部悬浮工具条：**☁️ 同步 / 🏠 网站信息 / 📄 页面管理 / 💾 备份恢复 / 🔑 修改密码**
14. **右上角 ⚙ 设置（替代了原来的「管理员」按钮）**：点导航最右侧的 **⚙** 弹出设置面板，两栏——**① 管理员模式**：进入（弹密码框）/ 退出，开启时齿轮变蓝带绿点；**② 界面版本**：**自动 / 手机版 / 电脑版**——自动按设备识别（手机自动进手机版，电脑自动进电脑版），也可手动固定（电脑上可预览手机版窄布局，反之亦然），选择存在浏览器里，下次打开仍生效。**手机版已全面适配**：正文绝不横向溢出（超宽表格块可左右滑动查看）、顶部 Word 工具条与底部管理条自动换行收紧、格式刷气泡改挂底部、拖拽把手放大到指尖可抓；**管理模式在手机上同样可用**——点块选中出工具条，⠿ 排序 / 文本框移动缩放 / 图片缩放旋转 / 列宽拖动都已做**触屏桥接**（手指按住把手拖动即可，不会误滚动页面）

> **⚠️ 以后改网页布局/设置，内容会消失吗？——不会。**
> 内容（文字、表格、图片、页面）保存在 `data/content.js` + 你的浏览器 + GitHub 仓库里，与布局代码（js/css）**完全分离**。以后更新代码、改外观，核心文档都不会丢；新代码也会自动兼容旧内容（缺的属性按默认值补齐）。重大改动前，可用「💾 备份 / 恢复」导出 JSON 再上一道保险。

## 三·补1、反馈与建议页（访客留言 + 管理员通道）

- **访客看到的是留言框**：称呼（可留空 = 匿名）、类型（提出问题 / 提建议）、内容（必填）、相关链接（选填）→ 点「**发送**」即提交，页面直接显示成功提示；**访客互相看不到别人的留言**
- **管理员通道**：管理员登录后，同一页底部出现「🔐 反馈处理」——每条反馈带编号 / 时间 / 类型 / 称呼 / 状态，可**改状态（待处理 → 处理中 → 已处理）**、**写小组回复**、**删除**，并可**📋 一键复制全部**（粘进「更新记录」或发群里）
- **⚠ 静态站限制**：反馈保存在**提交者那台浏览器**的本地存储里（纯静态网页没有服务器数据库）。同学们在你这台电脑之外提交的留言不会自动传过来 —— 演示 / 验收时在同一台电脑操作即可看到完整闭环；要真正跨设备收集，需后续接入云数据库（WorkBuddy 环节）或在页面上另留小组邮箱
- 反馈数据不进 `content.js`，与网站正文完全分离；「恢复初始内容」不影响已收到的反馈

## 三·补2、安全加固

- **CSP 内容安全策略**（index.html）：脚本只允许本站文件（外来注入脚本直接失效）、禁止 iframe / 浏览器插件 / 表单外提交流程 / 基址劫持，网络请求只放行本站与 GitHub API
- 所有访客留言在渲染前都经 HTML 转义（防 XSS 注入）；反馈里的链接只放行 http(s) 并带 noopener
- 全站外链统一 `rel="noopener noreferrer"`；referrer 策略收紧为 strict-origin-when-cross-origin
- 管理密码为 PBKDF2 v2 拉伸存储（见上）；GitHub Token 只在会话内、不落盘
- 注意：CSP 开启后 **Live Server 的自动刷新会失效**（它靠向页面注入脚本实现），改完代码手动 **Ctrl+Shift+R** 即可；部署到 GitHub Pages 不受任何影响

### 三·补3、访客身份 · 讨论区 · 发言审核（v3）

- **设备身份码**：每位访客自动获得一个身份码（如「访客4821」，随机四位数），保存在自己浏览器里。默认用它当昵称，也可改成自定义昵称——**昵称每 7 天只能修改一次**；管理员后台能看到每条发言/反馈旁的身份码（🆔），用于确认「是不是同一个人」；身份码不展示给其他访客
- **📬 我的反馈**：访客提交反馈后，随时能在「我的反馈」里看到自己的留言、处理状态和**小组的回复**（不再发完就看不到；老留言自动归属本机身份码）
- **🗣️ 讨论区**（与反馈并列的新栏目）：大家可发帖交流，帖子下有**楼中楼回复**（像小红书/抖音，可回复别人，显示「回复 @昵称」）；所有人互相可见
- **发言审核**：
  1. **自动拦截**：内容命中敏感词库的发言直接发不出去，并提示还剩几次机会
  2. **连续 3 条被拦截 → 禁言 1 个月**（连击计数清零重新算）；**一个月内被禁言超过 3 次 → 永久屏蔽**

## 三·补5、条目级跳转（条目 ⇄ 条目映射）与协同编辑方案规划（2026-10-27）

**① 条目级跳转（本次新增，管理员工具栏「⇄ 跳转」按钮）**

- **怎么建（就像填两个空）**：选中一段文字 → 点 **⇄ 跳转** → 记为「起点」，气泡自动收起、提示去选终点；再到别处（**可以跨页面**）选中另一段文字 → 再点 **⇄ 跳转** → 记为「终点」，弹出确认气泡 → 点 **⇄ 建立跳转** 完成。「清空重来」可随时作废；气泡里列出全站已有跳转，点 ✕ 删除（起点上的虚线字一并还原成普通文字）。
- **规则**：同一起点**只能有一个终点**（对同一起点重复建立 = 更新目标，所以天然不存在“一跳多”）；**多个起点指向同一终点（多跳一）允许**。起点文字 ≤80 字，**可以带加粗/颜色/高亮/渐变等格式**（修复⑦），但不能骑跨来源引用/链接/已有跳转（会提示重选）；起点终点同一段文字会被拒绝。
- **访客怎么用**：起点文字渲染成**绿色虚线**（区别于蓝色虚线的来源引用），直接点击 → 平滑滚动到终点内容块（**终点是表格单元格时精确滚到那一格**）并**绿光闪一次**（1.7s）；跨页面跳转会先自动切页再滚。若终点块被删除/文字被改，会按终点文字全页搜索兜底，找不到则提示。
- **实现**：起点文字包行内标记 `[[j:ID,文字]]`（md.js 渲染成 `.jumplink`，直接编辑时 htmlToMd 反向还原，与来源引用同一套机制）；映射表存全站数据 `state.content.jumps`（`{id, from:{页面,块,文字}, to:{页面,块,文字}}`），随 commit 进浏览器存储与撤销历史。管理员模式下普通点击仍是编辑文字，**Ctrl/Cmd+点击**可试跳。
- 限制：Markdown 块暂不支持点选建立（提示改用普通文字块）；首页/大标题等非标准块位置用按文字找元素兜底。

**② 协同编辑方案分析（老师演示的 WorkBuddy 云服务 vs「某台设备当服务器」）**

- **方案 A（老师/截图那条路）：静态站 + 云数据库服务（推荐主路线）**。截图里的做法 = 网站仍是纯静态托管，另绑一个云服务：`cloud-config.js` 引云端 SDK（CDN，无需构建工具），云端建共享表 + 行级安全策略，前端「云优先 + 断网自动降级本机存储」。这套**完全可行**，而且本站反馈模块已在同一思路下预留（`lm_feedback_v1` 等 localStorage 键 + 将来接云库），只需把「页面内容 JSON」「跳转/讨论数据」同样推到云表即可实现**跨设备同步**。
- **真·多人同时编辑（WPS 式小光标）要再加两件事**：1) **实时通道**——云 SDK 若支持订阅/WebSocket 就用订阅，否则定时轮询（2~3 秒一次，课程作业完全够用）；2) **冲突策略**——不建议一上来做真正的 OT/CRDT（多人同改同一段的技术，工程量大），课程作业的合理做法是「**编辑占位锁 + 字段级后写优先**」：每人进入编辑时往云端写一条心跳记录（谁、在哪页、正在改哪个块，带时间戳），别人的页面上该块显示「某人正在编辑」的小光标/角标并暂缓覆盖，停写 10 秒视为释放；保存时按字段（块为单位）后写优先。这套用一张云表就能实现，效果已经很接近 WPS 的协作感。
- **方案 B（把某个人的电脑/手机当服务器）**：技术上可行（设备上跑个小服务 + 内网穿透），但**不适合当正式方案**——手机会休眠、换网就断、要装穿透工具且校园网 NAT 限制多、稳定性差；而方案 A 的云服务本来就是别人帮你在跑「永远在线的服务器」。方案 B 唯一合理的用法：**课堂演示兜底**——同一 WiFi/手机热点下，一台笔记本起本地服务，同学连同一个网访问 `http://笔记本IP:端口`，就能演示「实时同步」，不依赖任何外部服务。
- **结论**：主走方案 A（与老师演示同构，也和本项目「云优先 + 本机降级」的反馈模块设计一致），把「页面内容同步 → 编辑心跳/占位锁 → 字段级后写优先」分三步做；方案 B 只作为课堂离线演示的备用招。CSP 需在接入云 SDK 时把云服务域名加进 `connect-src` 白名单。

> 工程路径（历史）：**Yjs(CRDT) + y-indexeddb + y-webrtc 网状 Mesh + 自建 Cloudflare Worker 信令 + TURN 兜底**，5 人左右同时编辑。网站本体纯静态（Yjs 套件已本地化到 `lib/`，零 CDN 依赖）；信令部署一次、永久免费（Cloudflare 免费层）。**现行方案见三·补12**：y-webrtc 换成原生 WebRTC Mesh + CloudBase Broadcast 信令（国内直连），数据层与漏斗不变。

**① 架构摘要**
- **数据层**：Y.Doc（CRDT）按「`meta` + 每页一个 `page:<id>` 键」分片存放站点内容；**y-indexeddb 本地持久化先于网络同步初始化**（硬性顺序，`test_yjs.js`【3】守护）——关标签页不丢、离线编辑重连后自动 CRDT 合并。
- **传输层**：y-webrtc **网状 Mesh**（每台设备直连其他所有在线设备，**明确排除 Host 模式**——一部手机锁屏只断它自己，其他人继续协同）。信令 = **Cloudflare Workers + Durable Objects（WebSocket Hibernation API）**，仓库 `signaling-worker/`（worker.js + wrangler.toml）：免费层合规（DO 用 SQLite 存储），空闲连接休眠零 CPU 时长，`workers.dev` 常驻、没有 Render 那种 15 分钟休眠/几十秒冷启动（Render 方案已废弃删除）。信令只牵线（交换 SDP/ICE），**绝不碰文档数据**。
- **库本地化**：`lib/yjs.js`(114KB) / `lib/y-webrtc.js`(219KB) / `lib/y-indexeddb.js`(99KB)，由 `build-libs.js` 从 npm 包 esbuild 打包（全局名 Yjs / YjsWebRTC / YjsIndexeddb），index.html 相对路径引入；CSP 收紧回 `script-src 'self'`，断网也能打开页面。
- **TURN 兜底**：OpenRelay 公共凭据（无需注册；国内可能不稳，不可达时 ICE 自动跳过）。TURN 只是直连失败后的兜底，不是低延迟保证；直连恢复自动切回（徽章每 3 秒重探）。
- **通道状态机**：`getStats()` 判定 succeeded 候选对——host/srflx=直连（地址含 `:` 即 IPv6）、relay=TURN；左下角徽章实时显示 **P2P直连 · IPv6 / P2P直连 · IPv4 / TURN 中继 / 离线（本地可用）**。
- **Awareness**：在线人数与「谁在编辑哪一块」（✍ 彩色描边 + 名字角标）全部走 Yjs Awareness，无中心计数。
- **与旧通道关系**：远端更新走同一个漏斗（`LMCollab.applyExternal` → 块级后写优先合并 → 防打断 → 讨论区/花名册/屏蔽校验复用）；本机互连（BroadcastChannel）与 GitHub 云端照常；**GitHub 回传与实时协同完全解耦**。信令不可达 → 自动降级，功能不缩水。

**③ 风险边界（必读）**

- **GitHub Pages 不处理实时数据**、不按编辑次数收费。
- **不能承诺 100% 直连**，且**没有自有 TURN 时**：校园网 AP 隔离会挡 host 直连；手机流量常见对称 NAT，STUN 打洞成功率下降；全部失败时徽章显示「离线（本地可用）」——改动存本地 IndexedDB，恢复后自动合并（期间 GitHub 云端仍是兜底）。有 IPv6 时直连成功率显著更高（徽章会显示）。

> ▸ **协作规范（实测沉淀）**：内容同步「后保存的赢」——两人**同时改同一处**会互相覆盖；正确姿势是**分页面分工**（各改各的地图），同一页改完打声招呼。管理员之间互见修改约 6~15 秒，访客 90 秒~5 分钟，急看就硬刷新。


## 四、部署到 GitHub Pages（约 10 分钟）

1. 注册/登录 GitHub → 右上角 **+** → **New repository** → 起名如 `living-maps` → Public → Create
2. 仓库页点 **uploading an existing file**，把 `living-maps` 文件夹里**所有文件**拖进去 → **Commit changes**
3. 仓库 → **Settings** → 左侧 **Pages** → Branch 选 `main` + `/ (root)` → Save
4. 等 1-2 分钟，得到网址：`https://你的用户名.github.io/living-maps/`
5. 用**同学的手机（非校园网）**实测能不能打开（作业要求国内普通网络可访问）

## 五、配置"网站上直接改内容"（云端保存）

1. GitHub → 右上角头像 → **Settings** → 最底部 **Developer settings**
2. **Fine-grained tokens** → Generate new token：
   - Repository access 选 **Only select repositories** → 选你的仓库
   - Permissions → Repository permissions → **Contents: Read and write**
   - 生成后复制 token（只显示一次）
3. 打开你的网站 → 管理员登录 → **☁️ 同步到 GitHub** → 填用户名 / 仓库名 / 分支 main → 粘贴 Token → **保存并同步**
4. 以后在网站上改完内容点同步即可，GitHub Pages 自动更新，**不需要手动上传文件**

> 安全说明：Token 只保存在你当前浏览器的会话里，不写入代码；仓库是公开的，但 Token 在你手里，别人改不了。

## 六、修改代码后如何更新

- **只改内容**（文字、表格、图表、页面）：网站上操作 + 同步，**不用**碰代码
- **改了代码/样式**：GitHub 仓库页 → Add file → Upload files → 覆盖上传 → Commit（或用 Git 命令，以后再教）
